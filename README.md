# Park LU

**South Bethlehem & Lehigh parking, live.** A web app that shows students and visiting parents where, when, and for how long parking is available around South Bethlehem and the Lehigh campus.

> **All data is synthetic.** No real payment sessions, operator feeds, or vehicle data are used. The simulator is calibrated to published BPA and Lehigh Parking Services rules (rates, time limits, enforcement hours). Rates and hours that could not be verified against a published source are flagged as placeholders in `fixtures/seed.json`.

## Inspiration

Parking around Lehigh is hard to read from the curb. Meters in South Bethlehem run on two different pay systems (BPA's ParkMobile and PayByPhone, Lehigh's Passport), garages have different visitor rules, and game days and Family Weekend change everything. There are no sensors on the street. But every pay-by-hour session already says when someone parked and when their time runs out. That is enough to estimate how full a zone is.

## What It Does

- **Home:** live headline numbers (open visitor spaces now, zones with spaces opening soon) and a Data Sources section.
- **Live Map:** each parking zone is a dial showing percent free (green at 40% or more, amber 15-39%, red under 15%), updated live over Server-Sent Events. Tap a zone for its rate, time limit, spaces in use, and notes. A list shows spaces about to free up in the next 15 minutes.
- **Plan a Visit:** pick a destination (Zoellner Arts Center, Goodman Stadium, Alumni Memorial Building, 3rd Street shops) and an arrival time. Visitor-allowed zones are ranked by predicted availability, price, and walk time, with event warnings.
- **Explore:** an associative data model of every session. Select anything (zone, day, hour, event, stay length, outcome) and every other field, KPI, heatmap, and chart re-filters, with Back, Forward, and Clear All.
- **Demo:** trigger Game Day or Family Weekend to spike demand for 45 minutes and watch the map and the numbers react.

## How We Built It

| Folder | What it is |
|--------|-----------|
| `fixtures/` | `seed.json`: operators, facilities, 15 zones, rate rules, destinations, event templates, demand curves, scenarios. Generated by `build_seed.py`. |
| `api/` | FastAPI service, Python 3.13 with uv. Holds the in-memory nine-table data store, the session simulator, the prediction and recommendation logic, the associative engine (numpy), and the SSE stream. No ML library. |
| `web/` | Next.js 16 (App Router), React 19, TypeScript, Leaflet. System fonts, light and dark from the OS, no chart or UI library. |
| `docs/` | `integration.md` (real-data path), `demo-script.md` (timed presenter script), `requirements-status.md` (requirement-by-requirement status). |
| `supabase/` | Postgres schema and seed SQL for the deferred hosted build. |

The simulator generates 28 days of pay-by-hour sessions at startup (about 137,000, in about 1 second), then advances in real time every 2 seconds. Events are generated from recurring templates relative to today's date, so the demo never goes stale. Sessions flow through a `SessionSource` interface that carries only zone, start, paid-until, end, and event, never a plate or person.

## Run It

**Prerequisites:** [uv](https://docs.astral.sh/uv/) (installs Python 3.13 for you) and a Node.js version supported by Next.js 16, with npm. No accounts, API keys, or hosted services are needed (map tiles come from public, keyless CARTO/OpenStreetMap servers). There is no authentication in the local build, including on the demo endpoint.

Run these in two terminals:

| | Command | URL |
|---|---------|-----|
| API | `cd api && uv sync && uv run uvicorn app.main:create_app --factory --port 8000` | http://localhost:8000 (interactive docs at `/docs`) |
| Web | `cd web && npm install && npm run dev` | http://localhost:3000 |

(`uv sync` and `npm install` are needed only the first time.)

**Checks:** API tests: `cd api && uv run pytest`. Web type check, lint, and contrast check: `cd web && npm run check`. Production build: `npm run build`.

**Configuration:** every variable is optional; names are in `.env.example`. API: `SEED_PATH`, `HISTORY_DAYS` (default 28), `SIM_RNG_SEED` (default 7), `CORS_ORIGINS` (default `http://localhost:3000`). Web: `NEXT_PUBLIC_API_URL` (default `http://localhost:8000`).

To change zones, rates, or demand curves, edit `fixtures/build_seed.py`, rerun it with `python3`, and restart the API.

## Formulas

- **Estimated_Occupancy** = (number of active sessions in the zone) / (zone capacity). A session is active when `start <= now < end`. Raw sessions only, no correction factor.
- **Predicted_Occupancy** = min(1.0, Baseline_Occupancy x Event_Boost). Baseline_Occupancy is the historical average Estimated_Occupancy for the zone and hour-of-week (0-167, New York time), excluding samples inside an event window that impacts the zone. Event_Boost is the largest demand boost among events whose window (2 hours before start to 1 hour after end) contains the time, or 1.0. Predicted_Availability = 1.0 - Predicted_Occupancy.
- **Walk_Minutes** = ceil(straight-line distance in meters x 1.3 / 80). That is a 1.3 detour factor at 80 meters per minute. Zones beyond 25 minutes are dropped unless fewer than 3 remain.
- **Recommendation_Score** = 0.5 x Predicted_Availability + 0.2 x Price_Score + 0.3 x Walk_Score (default weights: availability 0.5, price 0.2, walk 0.3). Price_Score and Walk_Score are 1.0 minus the min-max normalized hourly rate and walk minutes across the candidates (1.0 when all are equal). Ties go to the shorter walk.

## Challenges We Ran Into

- **No real data.** Session data from the pay apps is not public, so we calibrated a simulator to published rules and checked it against targets: Main Street and East 3rd above 85% busy at midday, Morton Avenue under 40%, 15-40% of sessions leaving early, 5-20% overstaying.
- **Undercounting.** BPA accepts ParkMobile, PayByPhone, and pay stations. Pay-app sessions alone would undercount, so zones keep notes and the docs call it out.
- **Making a demo move on cue.** Game Day injects sessions synchronously so the map recolors within seconds, with each zone capped at 95% and shown with before and after numbers.
- **Associative exploration at speed.** A numpy column store with symbol tables answers selections over about 137,000 rows in roughly 11 ms.
- **Time zones.** Every timestamp is timezone-aware and hour-of-week is computed in New York time, including daylight saving transitions.

## Accomplishments That We're Proud Of

- A working end-to-end system from seed fixture to live map on one laptop, started with two commands and no accounts.
- Explainable prediction (history times event boost) with no machine learning.
- An associative Explore view with five value states and selection history.
- Privacy by design: only aggregate counts leave the API, and the session record has no plate or person fields.
- 62 passing API tests, including property tests for time, geometry, and event expansion; clean type check, lint, and production build on the web side.

## What We Learned

- A payment session's `paid_until` is a free signal for "spaces opening soon", which is the one number drivers want most.
- Honest synthetic data needs explicit calibration targets, and placeholders need to be flagged where they live.
- Designing for accessibility from the start (text with every color, 44 px targets, contrast checked by script, reduced motion and transparency) is cheaper than retrofitting it.
